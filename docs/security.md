# Security model

The dashboard reads your Docker socket and SSHes your hosts. Treat it as
infrastructure: run it on a private network or behind auth, never open to the internet.

## What it can reach

| resource | access | why |
| --- | --- | --- |
| local Docker socket | **read-only** mount | list containers + health for discovery |
| `project_roots` dirs | **read-only** mount | parse compose files; `git`/file standards checks |
| remote hosts | SSH, one forced read-only command | remote container list + host stats |
| `DATA_DIR` | read-write | its own data — projects, tasks, notes |
| `backup_receipts` | read-only | render backup health (the agent does the work) |

It never writes to a project it tracks, never runs anything from a compose or config
file it parses, and holds no backup credentials.

## Discovery keys

Generated by `scripts/setup-remote.sh`, one per host, used for nothing else. Constrained
server-side by construction with OpenSSH `authorized_keys` options:

- `command="/path/to/script"` — sshd runs only this, whatever the client asks for
- `restrict` — no pty, no agent/X11/port forwarding, no `~/.ssh/rc`
- jump-host exception (if needed): `permitopen="TARGET:22"` — that one destination, nothing else

Every `authorized_keys` change is **additive** — append a line, never modify or remove
existing ones, so your own access is never at risk. **Verify** the restriction after
installing it: an arbitrary command runs the forced script instead; `ssh -tt` is
refused; a port-forward to anywhere but the permitted target is refused.

## Standards checks

Check *types* are a fixed set of named functions (`src/lib/checks/registry.ts`).
`standards.yml` can enable, label, and grade them — it **cannot** introduce logic that
runs shell or arbitrary code. Adding a check is a code change and a PR.

## Auth

No user database. Sign-in is an OAuth/OIDC round-trip to a provider you choose, then an
email allowlist. With no provider configured the app is fully open — only acceptable
when it's unreachable from the internet. See [auth](auth.md).

## Reporting

Open a GitHub issue describing the class of problem — not a working exploit.
